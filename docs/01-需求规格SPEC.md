# 缠论分析工具 · 需求规格 SPEC

> 本文档由 2026-09-05 的苏格拉底式需求访谈（见 [[项目/缠论分析工具/06-需求访谈记录|06 需求访谈记录]]）汇总而成，已经本人确认。改动需同步更新 [[项目/缠论分析工具/05-决策记录|05 决策记录]]。

## 1. Problem Statement（问题陈述）

本人做 A 股和港股的实盘交易，希望用缠论辅助盘后复盘和寻找买卖点，但存在三个障碍：

- **门槛高**：缠论的包含处理、笔、线段、中枢划分规则繁琐且有歧义，人工在多个级别上逐根划分既耗时又容易出错；本人对理论也不够熟。
- **黑盒**：市面上的缠论插件 / APP 只给结果不给理由，规则不透明、不可配置，无法判断它画得对不对，也学不到东西。
- **不可验证**：没有可以对照的基准，看到买卖点信号也不知道该信几分。

值得解决的原因：把主观、耗时的结构划分交给确定性算法，把人的精力留给决策；通过"每个买卖点附成立理由"实现边用边学，让工具的输出可解释、可验证、可质疑。

## 2. Proposed Solution（方案描述）

### 2.1 核心思路

一个本地运行的 Python 工具：输入股票代码，自动完成 **K 线包含处理 → 分型 → 笔 → 线段 → 中枢 → 走势类型 → MACD 背驰 → 三类买卖点** 的全链路计算，在多级别 K 线图上叠加绘制，并对每个买卖点给出分档规则满足度（严格 / 疑似，指规则满足程度而非胜率）和成立理由。计算引擎与展示层严格解耦，引擎输出结构化 JSON。

### 2.2 关键决策（已确认）

- **市场与级别**：A 股 5 分 / 30 分 / 日 / 周；港股 日 / 周。采用 K 线周期近似法；多级别联立通过"高一级中枢区间与笔端点半透明投影到当前图"实现。
- **笔**：老笔为默认，新笔可开关切换。**线段**：标准特征序列法（含缺口的第一 / 第二种情况）。**中枢**：笔中枢 + 段中枢。
- **买卖点**：一 / 二 / 三类买卖点，分"严格成立"和"疑似 / 待确认"两档，用颜色区分；图上显示一句话理由，点开显示结构化判定清单 + 教学式说明（含哪些条件是勉强满足的）。
- **已确认 / 未确认**：当下可能重画的笔、段、中枢在图上明确区分（实线 / 虚线）。
- **正确性基准**：自研引擎，用 chan.py / czsc 在同配置下的结果做交叉验证（作为测试 oracle，不作为运行时依赖），所有差异逐条解释。
- **自选股池**：以手动录入为主（网页搜索框加入或直接改 `watchlist.yaml`），提供通用的"粘贴代码列表 / 导入 txt"批量加入；不对接任何行情软件账号（本人自选股主要在东方财富，可手动录入）。
- **数据来源**：A 股历史（含 5 / 30 分钟）用 baostock（前复权），盘中补最新 K 线用东方财富接口（akshare）；港股日 / 周线用东方财富接口（akshare），yfinance 备源；股票列表与交易日历来自 akshare / baostock；本地 SQLite 缓存，手动触发增量更新。
- **运行环境**：本机 Mac 手动启动；架构不堵死"常驻定时更新 + 服务器部署"的路径。

### 2.3 入口设计

- **统一命令 `chan`**：`chan ui`（启动 Streamlit 网页）、`chan plot 代码 -l 级别`（生成单股静态 HTML）、`chan pool`（自选股池批量生成 + `index.html` 总览）、`chan update`（拉数据入库）、`chan import 文件`（批量导入代码）、`chan verify 代码`（与 chan.py 交叉验证）。
- **桌面双击启动器** `启动缠论工具.command`，等价于 `chan ui`。
- **网页首屏**：左侧自选股池（带最新信号徽标）+ 搜索框 + 参数区；主区级别切换按钮 + K 线大图（笔 / 段 / 中枢 / 买卖点 / 高一级投影 / MACD 图层可开关）+ 买卖点列表（点击定位、"详情"展开判定清单与教学说明）；记住上次查看的股票与级别；URL 带 `?code=&level=` 可直达。

### 2.4 分阶段交付（每阶段需本人看图确认后才进入下一阶段）

- **阶段 0**：数据层验证——实测 baostock / akshare / yfinance 对 A 股分钟线和港股日线的可用性、历史长度、复权处理；搭好 Provider 抽象与本地缓存。
- **阶段 1**：引擎 v1（包含处理、分型、老 / 新笔、笔中枢）+ plotly 静态交互 HTML + 与 chan.py 的交叉验证报告。
- **阶段 2**：线段 + 段中枢 + 四个级别 + 高级别投影 + `chan pool` 总览页。
- **阶段 3**：走势类型、MACD 背驰、三类买卖点（两档规则满足度）+ 简短 / 详细理由。
- **阶段 4**：Streamlit 网页——自选股切换、级别切换、参数开关、手动刷新、买卖点列表与详细理由面板。
- **阶段 5（后续，本期不做）**：定时自动入库、FastAPI + KLineChart 专业前端、并排联动、手机端访问、复盘笔记、港股分钟级。

## 3. Technical Constraints（技术约束）

- **运行环境**：本人 Mac 本机，Python 3.11+，手动启动；设计上须可迁移到云服务器 / NAS 常驻运行。
- **团队与节奏**：单人项目——AI 负责编码与测试，本人负责看图验收；无固定截止日期，以阶段门禁推进。
- **数据源**：仅使用免费源。免费接口不稳定且无 SLA，数据层必须做 Provider 抽象、失败切换和本地缓存；拉不到新数据时仍能用缓存出图并提示"非最新"。港股分钟级历史本期不获取。
- **技术栈**：引擎纯 Python（pandas / numpy）；阶段 1~3 用 plotly 出图；阶段 4 用 Streamlit；引擎输出 JSON，任何前端可复用。
- **理论口径**：级别用 K 线周期近似而非严格递归；买卖点"严格 / 疑似"阈值必须可配置且写进文档，因为缠论原文本身存在多义。规则权威源为 [[项目/缠论分析工具/02-缠论规则与实现口径|02 缠论规则与实现口径]]。
- **工程要求**：中文开发文档 + 架构说明 + 缠论规则实现说明（每条规则对应原文课次和取舍）；pytest 自动化测试覆盖核心算法，含 golden 文件与 K 线回放测试；便于日后交接。
- **实时性**：盘后为主，盘中手动刷新，延迟几分钟可接受；不做秒级实时。
- **存储位置**：代码与数据缓存放在 Obsidian 库之外（建议 `~/Desktop/web/chanlun/`），文档放本目录。

## 4. Non-goals（明确不做的事）

- 自动下单或对接任何券商交易接口
- 微信 / 邮件 / 手机推送提醒
- 历史回测、买卖点胜率统计
- 美股、期货、加密货币等其他市场
- 港股分钟级别（本期只做港股日 / 周）
- 北交所股票（4 / 8 开头代码本期不支持，输入时提示）
- 严格递归级别定义（保留接口，本期不实现）
- 多级别并排联动图（本期只做投影方式）
- 秒级实时行情、全市场扫描选股
- 对接任何行情软件的账号或自选股同步
- 手机端访问、多用户 / 公网部署、交易日志与复盘笔记：本期不做，但架构预留（Web 化路径、数据入库、服务可常驻）

## 5. Success Criteria（成功标准）

- **正确性**：固定样本集（约 10 只 A 股 + 5 只港股，覆盖趋势、震荡、涨跌停、停牌缺口等情形），在相同配置下与 chan.py 交叉验证：笔端点一致率 ≥ 95%，线段端点一致率 ≥ 90%，中枢区间一致率 ≥ 90%；所有不一致处都有书面解释，且本人认可该解释。
- **稳定性**：增量追加 K 线时，只有最后未确认的笔 / 段 / 中枢允许变化，已确认部分不得重画（用历史回放测试自动验证）。
- **阶段验收**：阶段 0~4 每个都经本人看图确认通过。
- **性能**：单只股票四个级别从本地缓存到出图 ≤ 3 秒；首次拉取一只股票全部级别的数据 ≤ 30 秒。
- **可用性**：在 Streamlit 页面中，一次点击即可切换自选股或级别；每个买卖点能看到颜色分档、一句话理由，点开后能看到判定清单与教学说明。
- **可解释性 / 学习效果**：本人能仅凭工具给出的理由说明，复述出任意一个买卖点的成立条件与薄弱环节。
- **可维护性**：一名不了解本项目的 Python 开发者，凭文档能在 1 小时内跑起来并理解架构；核心算法测试全部通过。
