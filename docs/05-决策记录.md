# 决策记录（ADR）

> 每条记录：背景 → 选项 → 决定 → 理由 → 可逆性。新决策追加编号，推翻旧决策时把旧条目状态改为「已替代」并链接新条目，不删除历史。

## ADR-001 级别采用 K 线周期近似，不做严格递归

- **状态**：已采纳（2026-09-05）
- **背景**：缠论原文中级别是递归定义的（次级别走势类型构成本级别中枢），K 线周期只是近似。
- **选项**：A. 严格递归；B. K 线周期近似 + 多级别联立；C. 两者都做。
- **决定**：B，递归只预留接口。
- **理由**：递归对底层划分极度敏感、重画严重；算日线级别中枢需要数月 5 分钟数据、周线需要数年，免费源拿不到，港股更不可能；主流工具也用近似法，与行情软件切周期的直觉一致。
- **可逆性**：中。`analyze` 的级别关系表可替换为递归实现，但买卖点的次级别逻辑需重写。

## ADR-002 笔默认老笔，新笔可切换

- **状态**：已采纳
- **背景**：老笔（顶底间至少 1 根独立 K 线）与新笔（分型不共用 K 线 + 原始 K 线 ≥ 3）画出的图差异明显。
- **决定**：两种都实现，配置项 `bi.mode`，默认 `old`。
- **理由**：老笔图更干净、边界问题少、主流开源实现默认值，便于交叉验证；新笔对快速反转敏感，留给本人对比后自选。
- **可逆性**：高，改配置即可。

## ADR-003 线段用标准特征序列法

- **选项**：A. 特征序列（第 67 课）；B. 1+1 终结；C. 线段破坏法。

## ADR-004 自研引擎，chan.py / czsc 只作交叉验证基准

- **状态**：已采纳
- **背景**：直接基于 chan.py 开发可省时间，但代码风格、文档、许可、耦合均不受控。
- **决定**：自研引擎；chan.py 装在开发环境作测试 oracle，不进运行时依赖。
- **理由**：本人要求完整文档、测试与可交接性；自研便于实现"理由生成"与"已确认 / 未确认"等定制需求；交叉验证仍能获得成熟实现的正确性背书。
- **可逆性**：中。若阶段 2 线段实现返工过多，可局部借鉴 chan.py 算法（需核对许可）。

## ADR-005 输出路线：plotly 静态 → Streamlit →（后续）FastAPI + KLineChart

- **状态**：已采纳
- **决定**：阶段 1~3 用 plotly 生成静态交互 HTML；阶段 4 用 Streamlit 包网页；专业前端留待阶段 5。
- **理由**：先把图画对是第一位的，静态方案开发最快、零部署；Streamlit 几乎不增加成本即可获得输入 / 切换 / 参数交互；引擎与展示解耦保证后续换前端不动算法。
- **可逆性**：高。

## ADR-014 代码与数据放在 Obsidian 库外

- **状态**：已采纳（2026-09-05）
- **背景**：本库内已有项目直接放代码（bomkit、jlc_bom_converter 含 .venv），但库已达 11G 且未配置排除规则；本人计划后续把所有项目统一迁到 `~/Desktop/web/`。
- **选项**：A. 代码放本目录子文件夹 + Obsidian 排除规则；B. 代码放 `~/Desktop/web/chanlun/`，文档复制一份到代码库 `docs/`，本目录保留备份。
- **决定**：B。代码库 `~/Desktop/web/chanlun/`，数据缓存在 `data/` 并 gitignore；`docs/` 为开发时引用的主文档，本目录为备份副本。
- **理由**：百万行级 SQLite 与虚拟环境不进笔记库索引与同步；与本人项目迁移方向一致；文档随代码走便于开发引用与交接。
- **可逆性**：高。

## ADR-015 采纳外部评审（Codex）对文档的修订

- **状态**：已采纳（2026-09-05）
- **背景**：Codex 通读七份文档后提出五点：笔中枢 / 线段交付顺序冲突、三买评级口径冲突、发生时间与确认时间未分离、多级别互调循环依赖、"置信度"措辞误导及交叉验证基准未固定。
- **决定**：
  1. 阶段 1 笔中枢为初版（不加不跨线段约束），阶段 2 补约束并重跑 golden。
  2. 三买严格档以本级别条件为准，次级别验证只用于二买。
  3. 所有结构增加 `confirmed_at`，图上区分发生时间与确认时间。
  4. `analyze()` 拆为 `analyze_level()`（单级别、不访问其他级别）与 `assemble()`（跨级别组装），缓存键加 `data_hash` 与 `as_of`。
  5. "置信度"统一改为"规则满足度"；chan.py 固定 commit 作基准；回放测试升为阶段 1 核心验收项。
  6. 笔已确认口径的潜在漏洞列为开放问题 6，由阶段 1 回放测试裁决。
- **理由**：均为会直接改变图与结论的口径问题，编码前解决成本最低。
- **可逆性**：高，均为文档级约定。

- **背景**：M0 实测东方财富行情接口在本机（Clash TUN 出口）被对端断连，网页可通但 API 不通；baostock、新浪、腾讯、yfinance 均可用。详见 `reports/M0-数据源实测报告.md`。

## ADR-018 笔中枢默认不跨线段

- **状态**：已采纳（2026-09-05），2026-09-06 补记
- **背景**：阶段 1 笔中枢初版 `bi_zs_cross_seg=True`；02 §5.2 与阶段 2 要求「不跨线段」。交叉验证时发现跨段口径与 chan.py `zs_algo=normal` 对不齐。
- **决定**：默认 `engine.zs.bi_zs_cross_seg=false`；需要旧行为时在 `config.yaml` 改回 `true`。
- **理由**：与 02 文档和 chan.py normal 模式一致；跨段只作对照开关，不再当默认。
- **可逆性**：高，改配置即可。
