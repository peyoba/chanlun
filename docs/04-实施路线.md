# 实施路线（v0.1）

> 原则：分阶段交付，**每个阶段必须经本人看图确认后才进入下一阶段**。每阶段的产出物、自动化测试和验收门禁在开工前定死；阶段内发现的规则差异回写 [[项目/缠论分析工具/02-缠论规则与实现口径|02 规则口径]]。工作量为粗估，用于排序而非承诺。

## 门禁流程（每阶段相同）

1. AI 完成开发 + 自动化测试全绿 + 交叉验证报告（如适用）。
2. AI 提交「阶段验收包」：样本集的图（HTML）、差异解释清单、本阶段变更的文档。
3. 本人看图，逐只样本确认 通过 / 有疑问；疑问逐条解释或修正。
4. 本人明确说"通过"，才开下一阶段。

## 阶段 0：数据层验证与骨架

**目标**：确认免费数据源能否支撑设计，搭出可运行的项目骨架。

**任务**
- 建代码库 `~/Desktop/web/chanlun/`，Python 3.11+ 虚拟环境，`pyproject.toml`，`chan` 命令骨架。
- 实测 baostock：5 / 30 分钟与日 / 周线的历史起点、前复权正确性、单股全量拉取耗时、每日更新时间。
- 实测 akshare 东方财富：A 股盘中 5 分钟接口、港股日 / 周线（前复权）、港股股票列表；对比 yfinance 港股日线一致性。
- 复权校验：挑一只近一年有分红除权的 A 股与港股，核对除权日前后价格连续性。
- 数据一致性校验：同一只股票同一级别，主源与备源在重叠区间逐根对比 OHLC（复权口径、时间戳是否为 K 线结束时间、交易时段边界、是否混入未收盘 K 线）；任何系统性偏差写入报告，主备切换不得产生假价格跳变。
- 实现代码归一化、Provider 抽象、SQLite 存储、`chan update`（增量 + 日线全量重拉）。
- 用样本集跑一遍 `chan update --all`，记录耗时与数据量。

**产出**
- 《数据源实测报告》（写入本目录 `07-数据源实测报告.md`）：各源可用级别、历史起点、限制、失败率、最终分工决定。
- 可运行的 `chan update`，样本集数据入库。
- 定稿样本集。

**验收门禁**：本人阅读实测报告并认可数据源分工；`chan update --all` 在本人 Mac 上跑通。

**风险**：baostock 分钟线起点不够早 → 缩短 5 分钟历史深度或改东财补历史；东财港股前复权异常 → 切 yfinance 为主。

**预计**：1~2 个工作日。

## 阶段 1：引擎 v1 + 静态出图 + 交叉验证

**目标**：把最确定的三层——包含处理、分型、笔——做对，并建立验证机制。

**任务**
- **先用一只 A 股日线（600519）跑通全链路**：数据 → 包含处理 → 分型 → 笔 → 图 → 回放测试 → chan.py 差异报告，再扩到全部样本与老 / 新笔。
- `engine/klines.py`、`fractal.py`、`bi.py`（老笔 / 新笔、`fx_check`）、`zs.py` 的笔中枢部分（初版，不加"不跨线段"约束，见 02 第 5.2 节）。
- `engine/models.py`（含 `confirmed_at`）与 `analyze_level()` 骨架（单级别），JSON 序列化。
- `render/plotly_chart.py`：原始 K 线 + 合并 K 线（可选显示）+ 分型标记 + 笔（实 / 虚线）+ 笔中枢框。
- `chan plot 代码 -l D --bi old|new`。
- 单元测试：包含处理（开头包含、连锁合并、一字板）、分型、老笔 / 新笔正反例、笔延伸与回退。
- golden 测试：样本集日线与 30 分钟的笔端点冻结。
- 回放测试（**核心验收项**）：逐根追加，断言已确认笔的端点永不变化；若因笔回退规则出现重画，按 02 开放问题 6 收紧口径并记录。
- 固定 chan.py 基准版本，写入 `tests/crossval/BASELINE.md`。
- `tests/crossval`：安装 chan.py，对齐配置（见 02 第 12 节），输出笔端点一致率与差异清单。

**产出**
- 样本集 × {日线, 30 分} 的 HTML 图（老笔、新笔各一套）。
- 《阶段 1 交叉验证报告》：一致率、每处差异的原因分类（口径差异 / 我方 bug / 对方 bug）。
- 02 文档第 1~3 节「验证记录」回填，开放问题 1 关闭。

**验收门禁**：笔端点一致率 ≥ 95%，差异逐条解释且本人认可；本人看图确认笔的划分"看起来对"；测试全绿。

**风险**：`fx_check` 与新笔计数口径对不上 chan.py → 以差异解释为准，不强求 100%。

**预计**：3~4 个工作日。

## 阶段 2：线段、段中枢、多级别与投影

**目标**：补齐结构层，四个级别可切换，高一级投影可见。

**任务**
- `engine/seg.py`：特征序列、包含处理、第一 / 第二种情况、未确认状态。
- `engine/zs.py`：段中枢、延伸 / 结束、升级 / 扩展提示。
- `assemble()`：级别关系表、高一级投影（中枢区间 + 笔端点时间映射）；各级别由 `analyze_level` 独立计算，互不调用。
- 笔中枢加入"不跨线段"约束，重跑阶段 1 golden，差异逐条说明。
- 绘图：线段（粗线）、段中枢（框）、投影（半透明色块）、级别切换按钮。
- `chan pool`：批量生成 + `index.html` 总览。
- 单元测试：线段第一 / 第二种情况、缺口作废、奇数笔约束；中枢 ZG / ZD、延伸、结束、回抽再入。
- golden / 回放测试扩展到线段与中枢。
- 交叉验证扩展到线段端点与中枢区间。

**产出**：样本集 × 四级别 HTML；`index.html`；《阶段 2 交叉验证报告》；02 第 4~5 节验证记录回填，开放问题 2、3 关闭。

**验收门禁**：线段端点一致率 ≥ 90%，中枢区间一致率 ≥ 90%，差异逐条解释；本人看图确认线段与中枢；回放测试证明已确认段 / 中枢不重画。

**风险**：线段第二种情况的边界实现最容易出 bug；特征序列包含处理口径分歧。预留返工时间。

**预计**：4~5 个工作日。

## 阶段 3：走势类型、背驰、买卖点与理由

**目标**：产出可用于决策参考的买卖点，两档规则满足度，理由可读。

**任务**
- `engine/trend.py`、`macd.py`、`divergence.py`（面积 / DIF 峰值 / 零轴回抽）、`bsp.py`（一 / 二 / 三类 + 类二买、两档判定、判定清单）。
- 次级别验证：调用低一级 `analyze` 结果；无低一级时归疑似档。
- `render/explain.py`：简短版 / 详细版 / 教学说明 / 薄弱环节模板。
- 绘图：买卖点标记（颜色分档、实心 / 空心）、悬停简短理由、页面下方详细理由表。
- 阈值标定：在样本集上统计严格 / 疑似分布，与本人一起定 `zero_band` 等阈值。
- 单元测试：每类买卖点正反例；交叉验证：买卖点与 chan.py 对照（仅参考）。

**产出**：样本集 × 四级别含买卖点的 HTML；《阶段 3 阈值标定与买卖点对照报告》；02 第 6~8 节验证记录回填，开放问题 4、5 关闭。

**验收门禁**：本人抽查至少 10 个买卖点，能仅凭理由复述成立条件与薄弱环节；严格档买卖点本人无"明显不对"的反对意见；疑似档比例不离谱（不出现满屏信号）。

**风险**：买卖点主观性最强，验收标准以"可解释、不离谱"为主，不以"准确率"为准。

**预计**：4~5 个工作日。

## 阶段 4：Streamlit 网页

**目标**：把静态能力包成日常可用的网页入口。

**任务**
- `ui/app.py`：左侧栏（自选股池 + 徽标、搜索、参数、更新按钮）、级别按钮、图、图层开关、买卖点列表、详情面板。
- `chan ui`、`启动缠论工具.command`、URL 参数、状态记忆。
- `chan import`（粘贴 / txt 批量导入）、UI 内加入 / 移除自选股、"保存为默认"。
- 盘中补数（东方财富当天 5 分钟聚合）与"含盘中未收盘数据"提示。
- 结果缓存，切级别不重算；性能测试 ≤ 3 秒。
- README / 开发文档 / 交接说明定稿。

**产出**：可双击启动的网页工具；文档齐全。

**验收门禁**：本人日常使用一周内无阻塞性问题；成功标准中的可用性、性能、可维护性项目全部满足。

**预计**：3 个工作日。
